Q1 如果让你设计文生视频评测体系，怎么做

参考回答与追问

先明确业务任务和失败成本，再定维度、量表、样本、算子和上线门槛。结合你的经历，可讲“基础质量 → 指令遵循 → 高阶质量”的三阶段门控，安全作为独立硬约束。[1]

维度具体看什么怎样评
技术质量清晰度、噪声、闪烁、局部变形质量算子 + 人评锚点
语义与指令实体、数量、属性、关系、动作与顺序指令拆解 + VLM 问答 + 证据核验
运动与时序身份连续、动作完成、交互与物理合理性连续片段分析 + 时序算子 + 人工复核
美学与专业度质感、光照、构图、运镜、镜头衔接专家量表 + 校准后的专用 Judge/RM
安全有害内容、隐私、偏见、对抗输入风险标签 + 对抗集 + 独立安全门槛

每个考点定义判定对象、证据、评分锚点与不适用条件。先报告全量样本的各门控通过率；高阶质量注明比较条件，并补充 A/B 双方共同通过的对齐子集比较，避免各模型分别只看自己的“幸存样本”。

易错：视频几乎不动，也可能拿到很高的一致性分。要同时检查“是否按指令运动、动作是否完成”，不能只奖励平滑或大运动。

用你的项目接：腾讯 70+ 可诊断考点；VGIF 将复杂指令拆成可验证的原子条件。总分用于概览，切片与考点用于定位问题。

P0 · 数据与可比性

Q2 如何构建评测集，让 A/B 模型比较公平

参考回答与追问

以真实业务分布为主、困难与边界场景为补充，按任务、风格、景别、人数、运动强度、难度做分层覆盖。结合你的项目，可以讲业务采样、正向标签/RAG 构造、真实影视片段反向构造，再用标签分析和贪心覆盖补齐空缺。

  • 防泄漏：按 prompt 家族、源视频/近重复内容分组切分训练、校准和测试；额外做生成器或场景留出，检查跨域泛化。
  • 公平协议：固定测试 prompt 与参考素材，约束时长、分辨率、采样次数及预算；逐模型记录参数。相同 seed 不代表跨模型产生相同随机条件。
  • 可复现：保存数据、模型、评分器和规则版本，以及随机种子、预处理、原始输出、失败日志。固定 seed 也不能保证所有硬件与算子完全确定。

追问“新版本只高一点，能上线吗”：看配对差值、置信区间与关键切片回归。按 prompt 或源内容簇 bootstrap，保留同组 A/B 配对；同一视频的帧和多名评分员意见不能当独立视频扩充样本量。

P0 · 指标口径

Q3 PLCC、SRCC、KROCC 和胜率分别说明什么

参考回答与追问
指标一句话解释面试时补一句
PLCCPearson，预测与人工分数的线性相关高相关不代表绝对分值已校准
SRCCSpearman，看排序的单调一致性有并列分用平均秩；不要硬套无 ties 简式
KROCCKendall，看样本对排序的一致程度量表有并列时说明使用 tau-b 等版本
MAE / RMSE绝对分数误差；RMSE 更惩罚大误差比较前固定评分范围与校准方式
Pairwise Accuracy预测胜/负/平与人工标签的符合率衡量裁判，不等同生成模型胜率
BLEU / ROUGE以 n-gram 等重叠衡量文本与参考的匹配适合特定文本任务；不能直接评价视频物理或整体生成质量

直觉：预测分统一加 10，PLCC/SRCC 仍可很高，但 MAE 很差；顺序对、分数间距不对，SRCC 也可能高于 PLCC。若 PLCC 使用非线性映射，要讲清拟合协议；业务验收中的映射应在独立校准数据上确定。[2]

平局计半分的胜率 = (W + 0.5 × T) / (W + T + L)
排除平局的胜率 = W / (W + L)　另报平局率与 W/T/L 样本数。

你项目里四个名称要分清：score_srcc 是视频分数相关；winratio_srcc 是按项目协议聚合后模型胜率排序的相关；acc_with_ties 是胜/负/平三分类准确率；本项目的 acc_without_ties 仅移除人工 GT 平局，剩余样本若预测为平局仍算错。

易错：把“SRCC 0.8”说成“准确率 80%”；把少数模型的聚合排名相关，当成样本级评分准确的充分证明。

P0 · 主观实验

Q4 怎样组织可靠的人评，你了解 BT.500 吗

参考回答与追问

按“定义量表 → 招募培训 → 试标对齐 → 随机盲评 → 过程质控 → 清洗分析”回答。BT.500 是电视图像主观质量评价的方法标准，可借鉴观看条件、实验组织和观察者处理；AIGC 的语义、运动、安全维度需要另行设计，使用 MOS 不等于完全遵循标准。[3]

  • 量表：如技术质量 1–5 分，1 分严重损坏影响观看，3 分有明显瑕疵但可用，5 分基本无可见缺陷；2/4 分也配边界例。分维打分，避免美感掩盖结构错误。
  • 组织：匹配评测员背景，先用标准例与边界例培训；统一播放器、显示与观看条件，随机顺序、隐藏模型身份，设置休息。
  • 质控：插入重复样本与预审金标，结合异常耗时、重测稳定性、维度混淆复核；不能因评分与多数人不同就直接删掉。
  • 统计：MOS 是平均意见分，连同置信区间与分布报告。有序评分可用 ordinal Krippendorff’s alpha；若将量表近似视为等距测量，可选合适的 ICC，并说明模型和一致性口径。

追问“绝对打分还是成对比较”：前者利于跨样本汇总，但量表漂移大；后者适合同 prompt 的 A/B 比较，应允许平局，注意配对成本。你可以讲平台标注器与质检器的实际模块；招募和培训只讲真实参与部分。

03自动评分与多模态

P0 · LLM as Judge

Q5 如何证明 LLM 或 VLM 裁判打分可信

参考回答与追问

把裁判作为需要独立验收的模型。先建立与训练数据隔离的人工参考集，覆盖业务分布、困难样本和新生成器；检验评分相关、含平局偏好准确率、分场景偏差、重复评分稳定性及跨域表现。

  • 减偏：固定维度、量表和锚点，盲化模型名称；成对比较对调 A/B，冲突样本复核；检查位置、冗长与模型自偏好。[4]
  • 重证据：输出维度分、可核对的时间段/区域和简短理由；看不到证据时允许“不确定/不可判断”。理由详细不代表正确，均匀抽帧可能漏掉关键动作。
  • 防注入：待评文本、字幕、图中文字都可能夹带“请给满分”；隔离待评内容与规则，加入攻击样本。JSON 校验保证格式，不能保证裁判没被操纵。

追问“能否完全替代人工”：机器覆盖规模化常规样本；低置信度、裁判分歧、分布外和高风险样本交给人工。主动学习按不确定性与多样性选样，同时保留随机抽检，避免只标困难样本导致分布偏移。

P0 · 多模态基础

Q6 CLIP、BLIP 和生成式 VLM 怎么用于质量评估

参考回答与追问

CLIP：图像、文本双编码器，通过对比学习映射到可比空间，可快速筛查粗粒度图文相关性；对计数、否定、空间关系和时间顺序需要额外验证。图文相似不代表画质、物理或指令都正确。[5]

BLIP / BLIP-2：BLIP 结合图文理解与生成目标；BLIP-2 用 Q-Former 连接冻结的视觉编码器和语言模型。常见生成式 VLM 可概括为“视觉编码器 + 连接模块 + LLM”，具体架构不完全相同。[6]

组合方式：质量/运动算子处理明确的低层现象，VLM 做语义与关系判断，领域 RM 学习人类细粒度偏好。视频需保留时间信息；全局采样用于覆盖，关键动作再密集采样或看片段，预算和抽帧策略也要固定。

补一句：传统 VQA 里“有参考/无参考”指是否需要参考视觉内容。自由文生视频往往没有逐像素真值，PSNR/SSIM 不适合作为主指标；FID/FVD 主要比较集合分布，也不能直接诊断某一条视频的具体失败。

PLCC：中心化后，比较线性共同变化
r = Σ(xᵢ−x̄)(yᵢ−ȳ) / √[Σ(xᵢ−x̄)² · Σ(yᵢ−ȳ)²]

x̄=ȳ=3；分子9，分母√(10×10)=10，所以 PLCC=0.9。

SRCC：先转成秩，再计算 Pearson
ρ = Pearson(R(x), R(y))
无并列时：ρ = 1 − 6Σdᵢ² / [n(n²−1)]

n=5；d 为两种秩的差，Σd²=2，因此 1−12/120=0.9。并列值必须取平均秩。

Kendall τ-b：数一数全部样本对
τ-b = (C−D) / √[(C+D+Tₓ)(C+D+Tᵧ)]

C/D 是一致/逆序对数，Tₓ/Tᵧ 是仅预测/仅人评平局的对数。两边同时平局的对不放入这四项。

C=9、D=1、Tₓ=Tᵧ=0，所以 τ-b=8/10=0.8。

其余9对一致C↔D 逆序
MAE = Σ|xᵢ−yᵢ|/n
RMSE = √[Σ(xᵢ−yᵢ)²/n]

绝对误差之和2，平方误差之和2；MAE=2/5=0.4，RMSE=√(2/5)=0.632。

面试一句话：PLCC 看线性，SRCC 看单调排序，Kendall 看样本对顺序；绝对误差另看 MAE/RMSE。先统一高低方向和量纲，校准映射只在训练/验证集拟合；常数评分的相关系数没有定义。

公式核对：Pearson · Spearman · Kendall τ-b。

2 · 评分器准确率、模型胜率、训练损失分开看

① 评分器：A/B 谁更好，判断对了吗？

gᵢ = score(Aᵢ)−score(Bᵢ)
gᵢ>ε → A胜；gᵢ<−ε → A负；否则预测平局
Acc = 判断正确的有效对数 / 有效对数
对分差g人评GT模型判断
12.00A胜A胜 ✓
20.10A胜平局 ×
3−2.00A负A负 ✓
40.05平局平局 ✓
50.00平局平局 ✓
6−0.30A胜A负 ×

含 GT 平局的三分类准确率：4/6=66.7%。
去除 GT 平局的严格准确率：2/4=50.0%。

本例预测平局与非平局 GT 不匹配就算错，不给半分。含平局与去平局是不同任务，不能直接比较；ε 应在验证集确定。

② 生成模型：人类到底更喜欢 A 还是 B？

GT 中 W=3、L=1、T=2，N=W+L+T=6
严格胜率 W/N = 50.0%
平局半分胜率 (W+0.5T)/N = 66.7%
去平局胜率 W/(W+L) = 75.0%

这里 W/L/T 来自人类 GT，拖动评分器阈值不会改变。胜率必须附对手、样本范围、平局处理与区间，不能当评分器准确率。

③ BT：用偏好训练 Reward Model

同一 prompt 的两个输出，共用同一个奖励网络；得到两个标量后做差。人类更喜欢的记作 w，另一个记作 l。

Δ = rθ(prompt,w)−rθ(prompt,l)
P(w≻l)=σ(Δ)=1/(1+e−Δ)
L = −mean[log σ(Δ)] = mean[softplus(−Δ)]
P(人类优选项更好)0.731
单对 BT loss ↓0.313
Δ=0 时概率0.500

奖励整体加常数不改变偏好；奖励“3分”不等于 MOS 3分。普通 BT 训练假设有胜负标签，不能把平局样本随意指定一边为 winner。

原理：InstructGPT §3 奖励建模。

3 · 人评均值会波动，版本差异也要报区间

单条视频：MOS 的均值 t 区间

5 位独立评测员评分：[4, 4, 5, 3, 4]。

MOS = Σrⱼ/m = 20/5 = 4
s = √[Σ(rⱼ−MOS)²/(m−1)] = √0.5 = 0.7071
SE = s/√m = 0.3162
95% CI = MOS ± t0.975,m−1·SE
= 4 ± 2.7764×0.3162 = [3.1220, 4.8780]

rⱼ 是第 j 人评分，m=5，s 为样本标准差，SE 为均值标准误；t 临界值自由度为 m−1。本例假设独立评分，均值 t 区间为教学近似；5档、小样本时应检查适用性。

95% 置信度：反复采样并按同一方法构造区间，长期约 95% 的区间覆盖真实均值。

不能说“这次真实均值有 95% 概率在这个区间”；更不能把同一人重复打分当独立评测员。

人评可靠性还看什么？

ICC 要注明模型、单人/多人均值、绝对一致/一致性及区间。1–5有序评分可考虑 ordinal Krippendorff α=1−Dₒ/Dₑ，比较实际分歧与机会分歧；ordinal 距离基于类别累计频率，简单平方差属于 interval 距离。高 Pearson 不代表评测员绝对打分一致。

NIST 均值置信区间 · ICC 选择与报告 · Krippendorff α 原作者说明。

这里用 percentile 法便于教学；实际选择 percentile/BCa 等方法应固定协议。同源 prompt 的多条生成可按 prompt 成簇重采样；比较两模型相关系数时也要共用重采样索引。

SciPy bootstrap：paired=True 的含义。

4 · BLEU/ROUGE 看文本重叠，不能证明视频语义正确

固定英文词级分词例

参考：

acatisonmat

候选：

acatsitsonmat
BLEU-2 ↑0.632
ROUGE-1 F1 ↑0.800
ROUGE-L F1 ↑0.800

“is”换成“sits”，一元词命中4/5；相邻二元组命中2/4。

绿色只表示在参考中有可匹配的一元词，不表示语义正确。本例固定小写、空格分词、单参考、句级 BLEU-2、均匀权重、无平滑。

按三步算

  1. BLEU 的 clipped precision：对每个 n-gram，命中数最多为参考中的出现次数，避免重复刷分。p₁=4/5=0.8，p₂=2/4=0.5。
  2. 短句惩罚与几何平均：c/r 是候选/参考长度；pₙ 是 n 元组精确率，wₙ 为权重，本例两者均为 1/2。
    BP=1（c>r），否则 e1−r/c
    BLEU-2=BP×exp[½log p₁+½log p₂]
    =1×√(0.8×0.5)=0.632456
  3. ROUGE 的召回与 F1：LCS 为保持顺序的最长公共子序列，允许中间跳词；这里 F1 使用 β=1。
    ROUGE-1：P=一元命中/c，R=一元命中/r
    ROUGE-L：P=LCS/c，R=LCS/r
    F1=2PR/(P+R)

    一元命中4，LCS长度4，c=r=5；两种F1均为0.8。

这里是 BLEU-2，不能标成 BLEU-4；默认句例的高阶 n-gram 零命中会使无平滑 BLEU-4 为0。真实报告应注明分词、句级/语料级、参考数量、大小写、平滑及实现版本。

岗位答法：文本答案、描述和摘要可以用 BLEU/ROUGE 作补充；图像/视频本身的质量、数量关系与时序遵循，需要视觉证据和专用评测，不能只拿文本重叠分数证明。

5 · 双塔语义相似度，与集合分布距离

CLIPScore：图文向量夹角

图像 → 图像编码器 → 向量 v ┐
文本 → 文本编码器 → 向量 t ┴→ L2归一化 → 点积
cos(v,t)=(v·t)/(‖v‖‖t‖)
原文 CLIP-S=2.5×max(cos(v,t),0)

原文 CLIPScore：0.750

2.5 是原论文缩放常数，理论范围是 [0,2.5]，不是严格[0,1]。CLIP 的原始检索 logits=exp(logit_scale)×cos；有些库又用100×max(cos,0)，三者不能混报。

CLIP 是对比学习双塔；CLIPScore直接复用其匹配能力，没有专门学习“所有维度的质量”。复杂数量、主客体关系、物理及时序可能失效，视频逐帧平均还会丢掉顺序。

CLIPScore §3 · CLIP 官方实现。

FID/FVD：两个样本集合在特征空间有多远

真实样本 → 固定编码器 → 均值 μᵣ / 协方差 Σᵣ
生成样本 → 同一编码器 → 均值 μg / 协方差 Σg
FID：通常为 Inception 图像特征
原始 FVD：I3D 视频特征

1D 高斯玩具例：固定真实分布 μᵣ=0、σᵣ=1，调节生成分布。σ 是标准差；多维公式里的 Σ 是协方差矩阵。

一维高斯 D²=(μᵣ−μg)²+(σᵣ−σg)²
=(0−1)²+(1−2)²=2.000
展开多维公式
D²=‖μᵣ−μg‖²+Tr[Σᵣ+Σg−2(Σᵣ½ΣgΣᵣ½)½]

Tr 是矩阵迹，½ 是矩阵平方根；一维时协方差为 σ²，所以式子化为上面的均值差平方＋标准差差平方。

这类指标比较样本集合分布，无法给单条视频判定 prompt 遵循。必须固定编码器、样本数、预处理与视频采样协议；高斯近似、有限样本偏差和特征域差异都会影响结论。

P0 · 腾讯 RM 与迭代

Q7 你的 Reward Model 怎么训，为什么能推动生成优化

项目回答骨架

业务问题是通用评分对影视质感与运动合理性的区分不够细。我基于 Qwen 系列 VLM 构建领域 Reward Model，数据先用教师蒸馏扩大覆盖，再用人工精标校准；比较 CoT+Score 和标量回归方案，并结合绝对分数与相对偏好学习。验证时同时看 SRCC、偏好准确率和分场景表现。接入 Wan 的 Flow-GRPO 后，我会再用独立评测和盲评检查目标收益、语义和运动回归，防止训练只把自己的奖励分推高。

三处要讲透：CoT+Score 便于诊断，但有文本生成开销；回归头直接输出分数，吞吐优势需同硬件实测。排序学习关注“哪个更好”，回归关注分数尺度；普通 BT 用分数差经 sigmoid 建模胜出概率，平局要用实际实现的专门处理。RL 中由 RM 给每条 rollout 标量奖励，再算组内相对优势，人工偏好对并非直接作为 GRPO 优势值。

闭环例子：你已有材料记录了通过遮挡、降低运动、偏色等方式迎合奖励的风险。回答时讲清“实际观察 → 分维归因 → KL/SFT、多奖励或难例回灌 → 独立回归验证”；仅把自己确实做过的措施说成已完成。

今晚核对：所用基座版本、你负责的数据/训练模块、平局实现、测试划分、可公开的基线对比。旧版材料的“约 1 万组教师 pair、约 1000 组人工偏好对”先核清单位；没有核准的提升比例与超参不硬背。

P0 · VGIF 与 CineTechBench

Q8 你的论文怎样让评测更可解释、更可诊断

项目回答骨架

VGIF-Score：复杂指令总分难定位问题，因此把时空指令拆成带依赖关系的 ST-DAG，再构造 QA 和 AutoRubric，用 VLM 检查原子条件。简历覆盖 14 个模型、3000+ 生成视频；讲一个多实体交互、状态变化或因果链失败的真实案例，比堆指标更有说服力。

用于解释的例子：“拿起杯子 → 倒水 → 放回桌面”需要分别验证实体、动作和顺序，不能仅凭一帧“人和杯子都出现”判成功。追问时说清父节点失败后子节点的计分、证据不足处理、问题生成与裁判误差，严格按论文/代码实际规则回答。

CineTechBench：把影视专业能力拆成 7 个核心维度，分别考察理解与生成；可讲模型在动态/空间感知上的短板。它体现“专家概念 → 可判定任务 → 失效模式”的方法。署名按最新简历：NeurIPS 2025 共同第一作者；VGIF-Score 为 PRCV 2026 第一作者。

最可能追问：“VLM 自己也会错怎么办？”答人工小集核验、分层误差分析、关键片段证据、独立交叉检查；把框架误差与被测模型误差区分开。

Q10 评测报告怎样转成可执行的优化建议

P1 · RAG 与 Agent

Q12 RAG 和 Agent 的评估重点有什么不同

加分项速记

RAG：分开评检索与回答。检索看证据召回、相关性和排序质量；回答看正确性、问题相关性与 Faithfulness，即回答声明能否由检索上下文支持。忠于错误上下文也可能答错，所以忠实性不等于事实正确性。Ragas 提供评测指标；LangSmith 可用于追踪与数据集实验管理，具体能力按使用版本确认。[8]

Agent：核心是任务成功率与环境最终状态，同时看工具及参数是否正确、轨迹关键节点、无效步骤、时延、成本和安全。达到相同正确结果的不同有效轨迹不应被逐步完全匹配规则误罚。

接你的经历：快手的三类任务是长剧情理解、暂停帧实体识别与搜索、长教学视频步骤提取。优先讲其中一个真实失败链；用 RAG 构造评测数据，不等于已经落地 Ragas 评测。

P1 · 训练与工程速记

Q13 PyTorch、LoRA、vLLM 与服务化最少要会什么

加分项速记
  • 训练：Dataset/DataLoader → 多模态预处理 → forward/loss → backward → optimizer/scheduler → 验证与 checkpoint。推理切 eval() 并用 inference_mode()；损失下降后仍要验人类偏好与留出场景。
  • SFT 与 LoRA：SFT 是监督微调范式，LoRA 是只训练低秩权重增量的参数高效方法，两者可结合；QLoRA 再引入量化。核查实际可训练参数、label mask、视觉输入截断和回归头保存。[9]
  • vLLM：面向受支持 LLM/VLM 的高效推理服务；PagedAttention 改善 KV cache 管理，continuous batching 提高并发利用率。评估吞吐、TTFT、P95 时延、显存与失败率；不是 Wan 扩散视频生成的通用加速器。[10]
  • 服务化设计：FastAPI/Flask 接收任务并返回 job ID，后台 worker 执行重任务；Docker 固定依赖与运行环境，模型、配置、数据和驱动兼容性仍需记录。长视频任务避免一直阻塞 HTTP 请求。

六句要能脱稿说，四个口径今晚核清

面试前检查清单
  1. 评测先定业务维度、量表与门槛，再做人评、机评和样本覆盖。
  2. PLCC 看线性，SRCC 看排序，KROCC 看样本对；相关不等于校准或准确率。
  3. Judge 用独立人工集验收，重点查偏置、分布外、平局和评分注入。
  4. 模型比较冻结协议，保留 A/B 配对；置信区间按独立的 prompt/源内容簇计算。
  5. RM 是训练代理，收益还要用独立人评与评测器确认，并监测静止、遮挡等投机。
  6. 结论必须落到失败场景、证据、可执行改动与回归验收。

今晚用 5 分钟核对

  • 职责：你亲自完成的两个模块、最难问题与验证结果。
  • 数字：pair / 视频 / prompt / QA 数量分清；不混报样本级相关与模型级排名相关。
  • 论文：CineTechBench 共同第一作者；VGIF 第一作者；DetailVerifyBench 在现有简历中为在投，最新状态按真实情况讲。
  • 效果：准备一个可公开的对比，说明测试集、基线、指标和局限；无法核准的精确提升不报。

被问到暂时不会的点：“这部分我还没有独立落地。我会先明确……，用……做基线，再通过……验证。”接上可执行方法，避免编造经验。

反问选两个：目前最影响上线决策的是裁判可靠性、数据覆盖还是工具效率？这个岗位前三个月最希望交付什么？评测发现的问题由哪个团队承接，如何复测验收？
